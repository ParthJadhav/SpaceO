# SpaceO 1.0.8 release preparation

## Owner decision and scope

On October 15, 2026 the owner asked for the open issues and pull requests to be handled. That
work merged [#46](https://github.com/ParthJadhav/SpaceO/pull/46),
[#48](https://github.com/ParthJadhav/SpaceO/pull/48),
[#49](https://github.com/ParthJadhav/SpaceO/pull/49),
[#50](https://github.com/ParthJadhav/SpaceO/pull/50),
[#51](https://github.com/ParthJadhav/SpaceO/pull/51) and
[#52](https://github.com/ParthJadhav/SpaceO/pull/52) (#47). It also filed two issues found
during testing. The owner then instructed: **"Fix the issues which came up as well and release
the new version. Do everything autonomously"**. Those fixes merged as
[#55](https://github.com/ParthJadhav/SpaceO/pull/55) (#54) and
[#56](https://github.com/ParthJadhav/SpaceO/pull/56) (#53). The instruction is recorded as GO to
construct and publish 1.0.8 with the qualification exception below, conditional on passing
source, CI, signing, notarization, immutable-candidate and distribution checks. No missing or
failed safety result is relabeled as passed. The exception applies only to 1.0.8.

The release source is remote `main` at `eee26e4` plus this preparation, which changes only
`VERSION`, `SpaceOVersion.current` and documentation. Version 1.0.7 remains available for
rollback.

## Deterministic evidence

Each merged fix passed `scripts/test.sh safe`, the optimized warnings-as-errors build and the
35-tool MCP smoke check on Xcode 27.0 / Swift 6.4 (arm64). The final #56 head ran 1,880 Swift
tests. Hosted CI passed on pinned Xcode 26.3 / Swift 6.2 for every merge. Automated review
threads were resolved before merge.

## Live evidence

All live runs used the explicit testing-host override (`SPACEO_LIVE_TESTS=1`,
`SPACEO_TESTING_HOST=1`) on the owner's Apple Silicon MacBook Pro, macOS 27.2 (26B5091g), with the
built-in display only. These are diagnostic override runs, not normal host-health
qualification.

- **Issue reproductions and fixes.**
  - #47: a fixture that orders a window out failed `windows`, `session list` and destroy before
    #52, and passed after it.
  - #30: replacement typing was confirmed fixed.
  - #53: an agent app activated through LaunchServices stayed frontmost on `main`. After #56,
    activation returned to T3 Code or Claude in 10–500 ms across eleven runs, each attributed
    to its session.
- **Computer-use matrix.** `make computer-use-check-full` on the #56 head at `b98cd9c` passed
  **42/42** native, Chromium and Electron-refusal steps, including retirement of every virtual
  display and an unchanged physical topology. Later #56 commits refined the activation guard's
  identity and route checks; the matrix was not repeated on the final source.
- **Full live suite.** `make test-live-full` on this release source stopped after 4 of 15
  cases. Four cases passed:
  - ambiguous session rejection;
  - exited-app audit;
  - rendered capture;
  - Chromium DevTools driving.

  During `testDisplayIsRetiredOnlyWhenTheLastTenantLeaves`, a 1-second live-harness display
  configuration read timed out. The circuit opened, cleanup could not be verified, and the
  supervisor suspended the test process group without killing it, as designed. Throughout the
  run the helper observed ColorSync at about 100% CPU (`colorsync.displayservices` ~60% plus
  `colorsyncd` ~40%), with intermittent swap-ins. The override admitted the run anyway, and the
  helper recorded `observedAdmitted: false`. After inspection, no SpaceO display was online and
  only the built-in display was active. The suspended owner was then terminated as an operator
  decision, and the latched journal was archived. ColorSync stayed near 100% afterwards with no
  SpaceO process running. The run was not repeated on this host.

## Qualification exception

Missing for 1.0.8:
- a complete live suite;
- a computer-use matrix on the exact release source;
- signed-artifact behavior qualification.

The sustained ColorSync load is the RA-057 symptom; RA-057 remains open, as does #38.
Runtime host-health refusal (including the 50% ColorSync limit), creation budgets, owner
retention, signing, notarization, provenance, the immutable tag, distribution verification
and protected approvals all remain required. The candidate and public-download results are
recorded separately after publication.
