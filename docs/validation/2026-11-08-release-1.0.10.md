# SpaceO 1.0.10 release preparation

## Owner decision and scope

On November 8, 2026 the untangle refactor [#67](https://github.com/ParthJadhav/SpaceO/pull/67)
was squash-merged to `main` as `645053e`, and the owner instructed: **"merge, deploy and create a
new version"**. This is recorded as GO to construct and publish 1.0.10 from remote `main` with the
qualification exception below, conditional on passing source, CI, signing, notarization,
immutable-candidate and distribution checks. No missing or failed safety result is relabeled as
passed. The exception applies only to 1.0.10.

The release source is remote `main` at `645053e` plus this preparation, which changes only
`VERSION`, `SpaceOVersion.current` and documentation. It was prepared in a fresh clone of
`origin/main`; unpushed local work on the development Mac is not part of it. Version 1.0.9
remains available for rollback.

Changes since 1.0.9:
- [#62](https://github.com/ParthJadhav/SpaceO/pull/62) retires the WindowServer-report admission
  check (by owner direction).
- [#63](https://github.com/ParthJadhav/SpaceO/pull/63) records the normal-admission runs on the
  cleaned host that met RA-057's closing condition (documentation only).
- [#67](https://github.com/ParthJadhav/SpaceO/pull/67) is a behavior-preserving refactor: one
  definition per MCP tool, shared limits and vocabularies, dead code and restating comments
  removed. The PR checked `tools/list` and every tool's accepted and advertised arguments
  against `main`.

## Version

Every release since 1.0.0 has been a patch-level maintenance release, including 1.0.9, which
added `spaceo safety clean-display-identities`. The supported surface is the signed DMG: the
CLI, daemon, MCP server and Viewer. #67 leaves the MCP tools, CLI help, refusal messages and
daemon protocol unchanged. The ~17 public `SpaceOKit` members it removed had no callers; the
module is declared as a SwiftPM library product but is not distributed, documented or supported
as a library, and earlier patch releases also removed `SpaceOKit` members. Following the
repository's convention, the version is `1.0.10`.

## Deterministic evidence

On the release source in a fresh clone (Apple Silicon, macOS 27.2):
- `make release-check` and `make release-dry-run` reported a consistent 1.0.10 configuration;
  `Tests/ReleaseSecurityTests.sh` and `Tests/LiveTestGateTests.sh` passed.
- The optimized warnings-as-errors build passed.
- The public privacy checks and `git diff --check` passed.
- `make verify-release` on Xcode 27.0 / Swift 6.4 (the toolchain recorded for 1.0.9): 1,919
  deterministic Swift tests with no failures, the supporting harnesses, the optimized build and
  the 35-tool MCP smoke check passed.
- An ad-hoc Viewer bundle reported 1.0.10 and passed strict signature checks; `spaceo version`
  reported 1.0.10.

The same suite under the machine's default toolchain (the `Xcode-26.6` bundle, Swift 6.4.2)
crashed the test process with signal 11 in
`AccessibilityBlackoutWindowTests.testSessionListSharesOneDiscoveryBudgetAcrossSessions`. It
crashes identically on `5d453eb`, before #67, so it is not introduced by this release; it is
recorded as a toolchain-specific test crash to investigate, not as a pass. Hosted CI and the
release workflow use the pinned Xcode 26.3 / Swift 6.2.

## Qualification exception

Missing for 1.0.10:
- the full live suite and the computer-use matrix on the exact release source;
- signed-artifact behavior qualification.

The release was prepared by an agent session that was itself using the owner's installed SpaceO
daemon on the active desktop. `docs/LIVE_TESTS.md` and the repository guide forbid live suites on
an actively used desktop, and the installed CLI, daemon and LaunchAgent were deliberately left
untouched. The normal-admission run that met RA-057's closing condition used a source build that
predates #67. In the display, input and private-API sources, #67 only removes uncalled code and
names existing limits; that is reviewed source evidence, not a live result.

#38 remains open. Runtime host-health refusal, creation budgets, owner retention, signing,
notarization, provenance, the immutable tag, distribution verification and protected approvals
all remain required. The candidate and public-download results are recorded separately after
publication.
