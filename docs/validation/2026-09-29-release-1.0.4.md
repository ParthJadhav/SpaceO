# SpaceO 1.0.4 release preparation

Status: **DRAFT — public publication is not approved by the required evidence.**

The owner requested a new release with release notes on September 29, 2026. This preparation
collects the reliability changes since public `v1.0.3` as a patch release. The installed 1.1.1
binary observed during host diagnostics is not a published GitHub release and does not determine
this repository's release numbering. The version file, embedded version, changelog, installation
example, and dedicated release notes are aligned to 1.0.4 on branch `release/1.0.4`.

## Included changes

See [release notes](../RELEASE_NOTES_1.0.4.md) for the user-facing summary and the
[reliability audit](2026-09-29-reliability-gaps.md) for implementation and diagnostic evidence.
The owner-lookup implementation is `efc51f4`; subsequent commits before this preparation only
record evidence. The patch also includes bounded configuration/diagnostic reads, launch reveal
and placement fixes, shared AX/restart budgets, and Viewer capture ownership cleanup.

## Verification

After the version update, the following checks passed locally:

- `make verify-release`: 1,683 deterministic Swift tests, supporting Python/shell/JavaScript
  checks, and the 34-tool MCP smoke check.
- `make release-check` and `make release-dry-run`.
- `Tests/ReleaseSecurityTests.sh` and `Tests/LiveTestGateTests.sh`.
- `swift build -c release -Xswiftc -warnings-as-errors`.
- Rebuilt ad-hoc Viewer bundle and strict/deep codesign verification.
- `git diff --check`.

Local signing/notarization inputs are absent, as reported by the dry run; it neither creates
nor verifies a distribution artifact. Candidate signing remains the protected workflow's job.

The local toolchain is Xcode 27.0 / Swift 6.4, not the pinned Xcode 26.3 / Swift 6.2 toolchain.
Earlier source diagnostics are scoped to their recorded commits. In particular, the 36-check
MCP pass and zero-leak exercised-daemon scan on `3e1306b` precede the owner-lookup fix. The final
combined workload was refused before daemon/display creation because host paging persisted.
The separate idle installed daemon was stopped normally. These observations are not a passing
final-source soak, Viewer leak scan, or signed-artifact qualification.

2. Complete the pending Viewer/capture workload, physical pointer checks, and cleanup evidence;
   resolve or obtain an explicit release-specific owner decision on outstanding findings.
3. Merge the final release source to `main`, then construct the immutable candidate through
   the protected release workflow when tag creation is permitted by repository instructions.
4. Verify the exact Developer ID-signed, notarized, stapled candidate, publisher signatures,
   Gatekeeper assessment, intended-distribution behavior, and rollback.
5. Record the release owner's final GO after reviewing that evidence. Update draft notices,
   dated changelog entry, and installation guidance before binding the final candidate.

No release tag or binary asset is created by this preparation. A GitHub draft may retain the
notes without publishing a tag. The publication workflow currently creates a new release;
remove that notes-only draft before approved workflow publication, after preserving its final
body in the checked-in release notes. Do not publish the draft manually or substitute locally
built artifacts for the verified workflow candidate. Version 1.0.3 remains the public latest.
