# SpaceO 1.0.4 release preparation

Status: **HOLD — system freeze investigation invalidates the earlier source-qualification conclusion. Nothing published.**

The owner forced a restart at 23:03 after reporting a stuck laptop. The investigation found an
earlier WindowServer watchdog and display-sync timeouts during the apparently passing workloads.
The assertion and bounded memory results below remain observations, not complete qualification.
See the [freeze investigation](2026-09-29-freeze-investigation.md). Live display work is paused;
a quiet sample after reboot does not clear this incident.

The owner requested a new release with release notes on September 29, 2026. This preparation
collects the reliability changes since public `v1.0.3` as a patch release. The installed 1.1.1
binary observed during host diagnostics is not a published GitHub release and does not determine
this repository's release numbering. The version file, embedded version, changelog, installation
example, and dedicated release notes are aligned to 1.0.4 on branch `release/1.0.4`.

  checks, and the 34-tool MCP smoke check.

- `Tests/ReleaseSecurityTests.sh` and `Tests/LiveTestGateTests.sh`.
- `swift build -c release -Xswiftc -warnings-as-errors`.
- Rebuilt ad-hoc Viewer bundle and strict/deep codesign verification.
- `git diff --check`.

Local signing/notarization inputs are absent, as reported by the dry run; it neither creates
nor verifies a distribution artifact. Candidate signing remains the protected workflow's job.

The initial local toolchain was Xcode 27.0 / Swift 6.4, not the pinned toolchain.
Earlier source diagnostics are scoped to their recorded commits. In particular, the 36-check
MCP pass and zero-leak exercised-daemon scan on `3e1306b` precede the owner-lookup fix. The final
combined workload was refused before daemon/display creation because host paging persisted.
The separate idle installed daemon was stopped normally. These observations are not a passing
final-source soak, Viewer leak scan, or signed-artifact qualification.

### Pinned-toolchain follow-up

After the owner completed Apple Developer authentication and downloaded Apple's archive,
Xcode 26.3 / Swift 6.2.4 was installed alongside the existing Xcode. The archive passed
`pkgutil --check-signature` as signed Apple Software. Qualification selects this toolchain with
`DEVELOPER_DIR`; the global Xcode selection was preserved.

Source `942e460ac2704324ac75469245d710b064e85bcc` passed `make verify-release` again on that
toolchain: 1,683 Swift tests and the supporting checks, including all 34 MCP smoke tools.
The optimized warnings-as-errors build, rebuilt Viewer strict/deep signature verification,
and resource sampler self-test also passed. PR CI
[36594508474](https://github.com/ParthJadhav/SpaceO/actions/runs/36594508474) passed its release
and secrets jobs on the pinned toolchain.

Under the owner's renewed idle-host reservation, read-only admission found normal memory
pressure, zero swap-counter deltas, and 15.02% combined ColorSync CPU. Doctor found the default
daemon stopped, lifecycle state `ready`, and only the original physical display.

The combined daemon/Viewer workload passed in 367.875 seconds: 1,277 operations, 404 captures,
four logical sessions, subscriber/load checks, logical session churn, static/animated/scrolling
Viewer phases, and verified topology restoration. All 317 Viewer samples reported a running
stream, an unoccluded window and a frame sink; peak sampled delivery was 29 fps. Both motion
phases required changing captured pixels. No resource sampler error was reported.

The daemon's sampled footprint peaked at 30.344 MiB and ended at 13.438 MiB after teardown.
Viewer peaked at 83.657 MiB and ended at 59.782 MiB before exit. During the capture soak,
footprints declined from 14.673 to 13.329 MiB for the daemon and from 83.548 to 59.485 MiB for
Viewer. Separate `leaks --noContent --nostacks` scans during the final capture-idle phase
reported **0 leaks / 0 leaked bytes** for each process. Those scans perturb that idle interval;
the numbers are a bounded observation, not proof of leak freedom or an explanation for the
earlier system slowdown.

The full MCP matrix then passed all 36 checks (44 tool calls) with zero failures, blocked
results or skips, in 44.832 seconds. Its private daemon was stopped normally after verified
cleanup. The post-run admission sample remained healthy: normal pressure, zero swap deltas,
and 21.19% combined ColorSync CPU. Evidence is retained privately in
`.artifacts/release-1.0.4/`, including `performance/`, `performance-report.json`, and
`source-matrix/`. These are source-build results; signed-artifact and physical Viewer pointer
qualification remain separate requirements.

The complete `make test-live-full` run subsequently passed all 16 cases, with no skips or
failures, in 1,470.617 seconds. The retained command and supervised test logs are
`live-command.log` and `live-tests.log` in the same private evidence directory. The host is an
Apple Silicon Mac17,9 with 24 GiB RAM, macOS 27.2 build 26B5091g. Accessibility and Screen Recording
were available; the deliberately disabled incompatible focus API remained disabled. This is
implementer testing in the owner's authorized existing graphical login, not an accepted host qualification.

Post-run doctor confirmed the original physical-only topology, lifecycle `ready`, and no running
daemon. A five-second health sample found normal memory pressure and zero swap deltas, but
69.71% combined ColorSync CPU, above the live-admission threshold. Further live work was paused
while remote CI and release preparation proceeded. This post-run sample is retained as a
refusal, not relabeled as a healthy admission. The later freeze investigation supersedes the
earlier plan to continue after a fresh quiet-host check.

2. Complete physical pointer checks and exact-candidate Viewer/capture and cleanup evidence;
   resolve or obtain an explicit release-specific owner decision on outstanding findings.

   Never move `v1.0.4` or imply that its already-built candidate contains later guard changes.
4. Verify the exact Developer ID-signed, notarized, stapled candidate, publisher signatures,
   Gatekeeper assessment, intended-distribution behavior, and rollback.
